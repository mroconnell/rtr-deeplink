APPROVED EDITOR REVIEW EXTENSION — 2026-09-23
The original worker contract above describes M1 intake. Ryan subsequently approved the following extension; docs/CONTEXT_CANDIDATES.md describes the final operator workflow.
ContextCandidateRevision holds immutable editor field snapshots, actor, candidate version and highest observed source id. The source observations remain immutable and separate. Save requires all 13 nullable CandidateReviewFields, expected_version, and explicit clear_conflicts for unresolved source conflicts left unknown. The dedicated timestamp field controls the saved RTR link; null means whole meeting, zero is valid. Review edits overlay source claims for lookup but never change the imported observations. New source research requires a new saved review before handoff.
POST /api/context/candidates/save verifies the Clerk editor then forwards to bearer/editor-gated /internal/context/candidates/save. Save locks the candidate, checks version, adds revision, invalidates lookup and rechecks after commit. Detail and prefill read under a coherent transaction/shared lock.
GET /context/new?candidate=ID&review=REV reads only the latest saved review with current research and a completed usable check. It prefills the existing editor without writing a ContextEntry. Stale/missing/blocked review shows an error rather than a blank publishing form. Missing or ambiguous meetings leave meeting link and match selection blank.
UI exposes Edit reviewed facts, Save review, Cancel, Open in Context editor, and a separate Watch proposed moment link when a matching meeting and valid timestamp are available. Unsaved edits disable handoff; recheck cannot overwrite an in-progress edit. A saved review is an editorial proposal, not automatic timestamp verification or publication.
