# WO-365 — BoardDocs video adapter (video-only, on-demand, never a scan)

Read scratchpad/briefs/preamble.md first, then docs/investigations/boarddocs_video_adapter.md on main (PR #1159, Breadth's spec — it is the source of truth for the mechanism), then the BACKLOG.md "Ship next" entry for BoardDocs (grep -n -i boarddocs BACKLOG.md), then CLAUDE.md's "Working conventions" (adapter rules: real live URL first, fixtures, wrapper platforms delegate via resolve_via_platform(), politeness rule). Your worktree has no .env; load the shared checkout's by explicit path if you need a token, never print a value. Never fetch youtube.com/youtu.be from this machine — a BoardDocs meeting whose video is YouTube is delegated by video id the way civicclerk.py/primegov.py do it (YouTubeAssetFinder.resolve_video_id / resolve_via_platform), and the drip Mac owns caption fetches; a Vimeo one delegates to vimeo.py (video-only, documented). Never download a media file.

## Why
Ryan wants BoardDocs-hosted meeting video reachable. Mechanism Breadth found (details in the spec): tenant flag bd.videoservice (1 = YouTube, 2 = Vimeo, 3 = other); meeting list via BD-GETMeetingsListForSEO; per meeting POST /{st}/{slug}/Board.nsf/VIDEO-GetAgenda with id=<meeting Unique> returns the video_id; a Referer header is required. Live examples: Tallahassee FL (fla/talgov, 6 of 6 recent meetings have video) and Colorado City AZ schools (az/ccschools, 5 of 40, newest June 2025). Negative controls Ryan named (flag on, no video id on the 40 newest): tx/austinisd (Vimeo flag), tx/nisd, mo/cscsdr6, ca/vusdca — expect no video; the adapter must return a clean "no video" for them, not an error.

## House rule — read this twice
go.boarddocs.com's robots.txt disallows all agents with crawl-delay 1000. The adapter reads ONE tenant, ONE meeting, on demand when a reader resolves a URL — like a browser visit. It never lists more than one tenant per call, never loops tenants, never runs as a sweep. Put that rule in the adapter's module docstring and in README's platform table row. No scanning script ships with this WO. During development, cap yourself at the 2 real tenants + 4 controls, one request at a time, ≥1 s apart.
