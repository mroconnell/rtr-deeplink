# Claude Inbox Triage

Auto-generated by a daily scheduled Routine (set up 2026-08-17) that reads
the `rtr-claude` Gmail label — Ryan forwards/filters operational and
third-party alert email here: Google Search Console, GitHub Actions
failure notifications, UptimeRobot, and (not yet seen a real example of,
as of this file's creation) Sentry. See `CLAUDE.md` for the full
Working-conventions bullet describing this Routine's behavior.

**Why this file is separate from `BACKLOG.md`/`CLAUDE_BACKLOG.md`,
deliberately:** this Routine runs unattended, once a day, opens its own
PR, and merges it itself once CI passes (0 approvals required by the
branch ruleset) — see `BACKLOG_DONE.md`'s "Branch ruleset on `main`"
entry for that ruleset's real history. Writing directly into `BACKLOG.md`
or `CLAUDE_BACKLOG.md` would risk colliding with whatever a concurrent
interactive session is doing to those same files (a real, previously-hit
problem — see `CLAUDE.md`'s "sometimes worked on by more than one
session" bullet). This file is the Routine's own dedicated space; nothing
else should need to edit it except that Routine and the promotion step
below.

**How entries get promoted**: this file is a staging area, not a
final destination. When a human (or a later session, explicitly asked)
reviews an entry here and it holds up, move it into `BACKLOG.md` (if
confirmed/actionable) or `CLAUDE_BACKLOG.md` (if still a genuine open
idea) in that file's own style — full write-up, not just a pointer — the
same promotion pattern `CLAUDE_BACKLOG.md`'s own header already
describes for itself. Once promoted, delete the entry from here rather
than marking it done in place, so this file only ever shows what's still
awaiting a look.

**Entry format** the Routine follows: one dated section per triage run
(only created when that run found something worth recording — a run
that found nothing new gets no section, not an empty one). Within a run,
one entry per finding, each explicitly marked **Confirmed** (root cause
traced in real code/logs — the Routine had a way to verify it directly,
e.g. GitHub Actions run logs) or **Unconfirmed** (reasoned from the
alert's own text plus this repo's code, but the alert's own dashboard
was behind auth the Routine couldn't reach, e.g. Google Search Console),
plus an explicit **Impact** line sizing the real or estimated scope,
consequence if unfixed, and rough fix effort — never just a description
with no sizing. Genuine open questions the Routine couldn't resolve
itself go in the entry as questions, not silently guessed at further.
