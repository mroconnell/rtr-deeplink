## 1. Search Console "Missing field" flags — `uploadDate` (Videos), `startDate` (Events)

**Backlog entry**: `BACKLOG.md`, "Reliability, ops & cost" →
"Search Console, structured data & SEO plumbing" (grep
`New "Missing field" flags`).

**Background** (from the entry, so you don't have to re-derive it): a
2026-08-21 code fix made a page with a null/unparseable `date` emit
*neither* `uploadDate` nor `startDate` in its structured data, instead
of emitting an invalid value. That traded Search Console's old
"invalid datetime value" flag for a new "missing field" flag on the
same underlying pages. The flag first appeared in Search Console
2026-08-31. Re-verified today (2026-09-11): still open, no closing
entry in `BACKLOG_DONE.md`, no code changes to
`archive/templates/meeting_page.html` since. This is the same shape as
the `thumbnailUrl` "Missing field" flag that closed itself out in
Search Console once its fix landed (`BACKLOG_DONE.md`,
2026-08-31 entry) — this is that same check, for the newer flag.

**Step 1 — Google Search Console → Videos enhancement report.**
Go to `search.google.com/search-console`, select the
redtaperecordings.com property. In the left sidebar, under
"Enhancements," click **Videos**. Look for an issue row reading
**"Missing field 'uploadDate'"** and note its **Affected items** count.
- **0 or not listed**: the gap isn't showing up as a live issue —
  nothing to do, can note this entry as low-priority/closeable.
- **A nonzero, meaningful count**: confirms the trade-off is real at
  scale. Worth a follow-up session running
  `GET /internal/date-format-audit` (needs the `ARCHIVE_INGEST_TOKEN`
  bearer token) to get the exact null/unparseable-date page count
  before deciding whether to backfill, fix per-adapter date capture,

**Step 2 — Google Search Console → Events enhancement report.**
